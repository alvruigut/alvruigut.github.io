ACL Enumeración

Checklist para enumerar ACLs, ACEs, SIDs y permisos delegados que puedan derivar en rutas de escalada.

Aviso: las ACL se pueden enumerar de forma manual o con PowerView, pero mi forma favorita y la más cómoda para interpretar relaciones es BloodHound.

PowerView.ps1

Comandos

Import-Module .\PowerView.ps1

# Información General del Dominio. Mucho texto. No recomendado
Find-InterestingDomainAcl 

# Enumerar ACL del usuario alvaro
$sid = Convert-NameToSid alvaro
Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $sid} 
# Enumerar ACL del grupo: Help Desk Level 1
$hdlgroupsid = Convert-NameToSid "Help Desk Level 1"
Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $hdlgroupsid}

# Enumerar grupos anidado del grupo: Help Desk Level 1
Get-DomainGroup -Identity "Help Desk Level 1" | select memberof

# Crear una lista de usuario del dominio
Get-ADUser -Filter * | Select-Object -ExpandProperty SamAccountName > ad_users.txt
# Enumerar ACL de todos los usuarios de la lista que guarden relación con alvaro
foreach($line in [System.IO.File]::ReadLines("C:\Users\htb-student\Desktop\ad_users.txt")) {get-acl  "AD:\$(Get-ADUser $line)" | Select-Object Path -ExpandProperty Access | Where-Object {$_.IdentityReference -match 'INLANEFREIGHT\\alvaro'}}

# Búsqueda Inversa: Aplicar un valor a un GUID
# ObjectType: 00299570-246d-11d0-a768-00aa006e0529
$guid= "00299570-246d-11d0-a768-00aa006e0529"
Get-ADObject -SearchBase "CN=Extended-Rights,$((Get-ADRootDSE).ConfigurationNamingContext)" -Filter {ObjectClass -like 'ControlAccessRight'} -Properties * |Select Name,DisplayName,DistinguishedName,rightsGuid| ?{$_.rightsGuid -eq $guid} | fl

# Transformar CN=Lidia Jim en nombre de usuario del dominio lidjim
Get-DomainUser "Lidia Jim" | select samaccountname

Output

Enumeración encadenada sobre usuarios y grupos

Comandos

# 1. Enumerar ACL del usuario wley
$sid = Convert-NameToSid wley
Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $sid}
# wley tiene permiso ForceChange sobre el usuarios damundsen: Podemos cambiar su contraseña y conectarnos como ese usuario

# 2. Enumerar ACL del usuario damundsen
$sid2 = Convert-NameToSid damundsen
Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $sid2} -Verbose
# damundsen tiene permisos GenericWrite sobre el grupo Help Desk Level 1: Podemos agregar a wley o damundsen a ese grupo para continuar con el ataque

# 3. Enumerar ACL del grupo Help Desk Level 1
$hdlgroupsid = Convert-NameToSid "Help Desk Level 1"
Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $hdlgroupsid}
# No encontramos nada
# 3.1 Enumerar grupos anidado de Help Desk Level 1
Get-DomainGroup -Identity "Help Desk Level 1" | select memberof
# Help Desk Level 1 tiene de grupo anidado al grupo Information Technology: CN=Information Technology,DC=INLANEFREIGHT,DC=LOCAL

# 4. Enumerar ACL del grupo Information Technology
$itgroupsid = Convert-NameToSid "Information Technology"
Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $itgroupsid}
# usuarios que pertenecen al grupo Help Desk Level 1 -> Information Technology tienen permisos GenericAll sobre el usuario adunn

# 5. Enumerar ACL del usuario adunn
$adunnsid = Convert-NameToSid adunn 
Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $adunnsid} -Verbose
# adunn tiene permisos DCSync sobre el dominio. Puede dumpear NTDS.dit del DC
