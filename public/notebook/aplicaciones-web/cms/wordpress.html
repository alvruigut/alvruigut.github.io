Nmap

# Enumeración básica
nmap -sV --script http-wordpress-enum <url>

# Escaneo de vulnerabilidades
nmap --script=http-vuln* -p 80,443 <url>
nmap -sV --script "http-wordpress* and not http-wordpress-brute" <url>

# Enumeración de usuarios
nmap -sV --script http-wordpress-users <url>

# Escaneo de plugins en la ruta http://ip/wordpress
nmap -p80 --script http-wordpress-enum --script-args http-wordpress-enum.root='/wordpress',search-limit=1000 <ip_target>

WPScan

WPScan

# Enumeración básica
wpscan --url <url_wordpress>

# Enumeración de usuarios
wpscan --url <url_wordpress> -e u
wpscan --url <url_wordpress> -U <user> -P /usr/share/wordlists/rockyou.txt
wpscan --url <url_wordpress> -e u --passwords /usr/share/wordlists/rockyou.txt

# Enumeración de plugins vulnerables y usuarios
wpscan --url <url_wordpress> -e vp,u
wpscan --url <url_wordpress> -e vp,u --plugins-detection aggressive
wpscan --url <url_wordpress> -e vp,u --plugins-detection aggressive --api-token=<token>
wpscan --url <url_wordpress> -e vp,u --plugins-detection mixed --api-token=<token>

# Plugins, complementos y temas
wpscan --url <url_wordpress> -e p
wpscan --url <url> -e ap
wpscan --url <url> -e t

# Bypass de bloqueos
wpscan -u <url_wordpress> --username <user> -w /usr/share/wordlists/rockyou.txt --random-agent

El API token de WPVulnDB permite superar límites de consultas diarias en WPScan.

Directorio wp-content personalizado

wpscan -u <url_wordpress> --wp-content-dir "directorio-personalizado-wordpress"

Fuerza bruta login

wp-login prueba contra el panel web. xmlrpc usa /xmlrpc.php y suele ser más cómodo si wp.getUsersBlogs está habilitado.

Comprobar XML-RPC

# API activa
curl "http://<target>/xmlrpc.php"

# wp.getUsersBlogs activo
curl -X POST "http://<target>/xmlrpc.php" -d@test.xml

# test.xml
<?xml version="1.0" encoding="utf-8"?>
<methodCall>
<methodName>system.listMethods</methodName>
<params></params>
</methodCall>

WPScan fuerza bruta

wpscan --url <url/wp-login.php> -U <user> -P <pass.txt> --password-attack xmlrpc -t 20
wpscan --url <url/wp-login.php> -U <users.txt> -P <pass.txt>
wpscan --url <url/wp-login.php> -U <admin>,<david> -P <pass.txt> --password-attack xmlrpc -t 20

Hydra

hydra -L <users.txt> -P <pass.txt> <url> http-post-form "/wp-login.php:log=^USER^&pwd=^PASS^&wp-submit=Log In:F=incorrect"

Hardening de WordPress

RolDescripción
AdministradorAcceso a funciones administrativas, gestión de usuarios, publicaciones y código fuente.
EditorPuede publicar y administrar publicaciones, incluidas las de otros usuarios.
AutorPuede publicar y administrar sus propias publicaciones.
ContribuyentePuede escribir y administrar sus publicaciones, pero no publicarlas.
AbonadoUsuario normal que puede explorar publicaciones y editar su perfil.

Actualizaciones automáticas

define( 'WP_AUTO_UPDATE_CORE', true );
add_filter( 'auto_update_plugin', '__return_true' );
add_filter( 'auto_update_theme', '__return_true' );
  • Deshabilitar el usuario estándar admin y usar nombres menos predecibles.
  • Imponer contraseñas robustas y 2FA.
  • Aplicar mínimo privilegio en usuarios y revisar permisos periódicamente.
  • Limitar intentos de login y restringir wp-login.php por IP cuando sea posible.
  • Valorar plugins defensivos como Sucuri, iThemes Security o Wordfence.
