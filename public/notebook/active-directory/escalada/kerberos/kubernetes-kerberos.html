Kubernetes y Kerberos

Notas para configurar Kerberos desde Kali y usar tickets cuando el acceso con usuario y contraseña falla en servicios del dominio.

Info: Conexión con user:password en el dominio falla

SSH: Permission denied (gssapi-with-mic,keyboard-interactive)

SMB: STATUS_NOT_SUPPORTED / STATUS_NOLOGON_WORKSTATION_TRUST_ACCOUNT

WINRM: No responde

Trataremos de usar Kubernetes para conectarnos a través de Kerberos 88 generando un ticket

Modificar /etc/hosts

<ip_dc> <hostname>.<domain> <domain>

Configurar Kerberos: /etc/krb5.conf

[domain_realm]
    .<domain> = <DOMAIN>
    <domain> = <DOMAIN>
 
[libdefaults]
    default_realm = <DOMAIN>
    dns_lookup_realm = false
    dns_lookup_kdc = true
    ticket_lifetime = 24h
    forwardable = true
 
[realms]
    <DOMAIN> = {
        kdc = <HOSTNAME>.<DOMAIN>
        admin_server = <HOSTNAME>.<DOMAIN>
        default_domain = <DOMAIN>

Ajustar Reloj

ntpdate <ip_dc>
systemctl stop systemd-timesyncd

Generar Ticket TGT del usuario f.frizzle

impacket-getTGT <domain>/'user':'password' -dc-ip <ip_dc>
# Exportar Ticket a la variable de entorno  
export KRB5CCNAME=<user>.ccache

Conexión con la flag -k

# Ya podemos acceder a los servicios con la flag -k. Ej SMB
nxc smb <ip_dc> -u 'user' -p 'password' -k 
# Login SSH con ticket Kerberos
ssh <user>@<ip_dc> -k
