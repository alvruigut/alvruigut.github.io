Metasploit

1. Ver interfaces de red

Meterpreter: ver interfaces de red

ipconfig

2. Autoroute

Meterpreter

run autoroute -s <red_interna>/24
run autoroute -p

Metasploit

route add <red_interna> <mascara_subred> <session_id_meterpreter>
route print # Vemos las rutas activas

3. Escanear red interna

Enumerar hosts: one-liner

# Bash
for i in {1..254}; do (ping -c 1 -W 1 10.10.10.$i | grep "64 bytes" &) 2>/dev/null; done
for i in {1..254}; do (ping -c 1 -W 1 10.10.10.$i | grep "bytes from" &); done

# CMD
for /L %i in (1,1,254) do @ping -n 1 -w 200 192.168.0.%i > nul && echo 192.168.0.%i is up.

Metasploit: enumerar puertos

use scanner/portscan/tcp
set RHOSTS <ip_victima_final>
run

Proxychains: preparar escaneo con Nmap

# Kali
cat /etc/proxychains4.conf

# Recomendado:
# Descomentar: dynamic_chain
# Comentar: strict_chain
# Añadir al final:
# socks4 127.0.0.1 9050

Metasploit: levantar proxy SOCKS

Kali: escaneo a través del pivote

proxychains nmap <ip_victima_final> -sT -Pn -sV -p 445

4. Port-forwarding

Meterpreter

# -l <puerto_local> -p <puerto_objetivo_victima_final> -r <ip_victima_final>
portfwd add -l 5000 -p 80 -r 10.10.10.5
portfwd list # Listar port-forwardings activos

# Nos hemos traído a nuestra máquina atacante Kali el puerto 80 de la víctima final.
# Desde el navegador veremos en localhost:5000 la web de la víctima final en el puerto 80.

Una vez que Metasploit tiene una ruta hacia esa red mediante autoroute o route add, los módulos pueden abrir conexiones TCP directamente contra la IP interna y el puerto objetivo a través de la sesión comprometida.

El port-forwarding sirve para traer un servicio concreto al localhost de la máquina atacante. No es necesario para que Metasploit alcance SSH si ya puede enrutar tráfico TCP a través del pivote.

Si queremos conectarnos desde Kali por SSH a la máquina víctima final, sí haría falta port-forwarding o usar Proxychains.

Ojo con los payloads: en escenarios de pivoting suele ser más práctico usar payloads de tipo bind, porque la víctima final normalmente no tiene conectividad directa de vuelta hacia la máquina atacante.

5. Montar escenario de prueba

  • Máquina Linux atacante
  • Máquina Windows 7 vulnerable intermedia
  • Máquina Windows 7 vulnerable final

Desde VMware montamos los tres sistemas operativos y configuramos las redes para crear el escenario de prueba.

Máquina Linux atacante: ponemos la red en modo Bridged con una sola interfaz.

Máquina Windows 7 vulnerable intermedia: ponemos una interfaz en modo Bridged y otra en NAT, creando una red NAT propia con una IP de red, por ejemplo 10.10.10.0/24.

Máquina Windows 7 vulnerable final: conectamos una sola interfaz a la misma red NAT que la máquina intermedia.

Finalmente comprobamos que mediante ping la máquina Linux tenga accesibilidad con la máquina intermedia, pero no con la máquina final. La máquina intermedia debe tener conectividad con ambas mediante ping.
